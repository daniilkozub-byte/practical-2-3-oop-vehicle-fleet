## Крок 1. Клас `Vehicle` — інкапсуляція (~15 хв)

**Пояснення.** Інкапсуляція — це коли поля класу закриті (`private`) і недоступні напряму ззовні, а працювати з ними можна лише через методи класу (конструктор, геттери). Це захищає об'єкт від встановлення некоректних значень.

**Завдання.** Створіть клас `Vehicle` з полями:

- `inventoryNumber` — інвентарний номер (String);
- `brand` — виробник (String);
- `model` — модель (String);
- `year` — рік випуску (int);
- `fuel` — кількість палива (double).

Вимоги:

- усі поля — `private`;
- конструктор, що ініціалізує всі поля;
- метод `getInfo()`, який повертає рядок з інформацією про техніку;
- метод `refuel(double amount)`, який збільшує `fuel` (кількість палива не може стати від'ємною — перевірте це і в конструкторі, і в `refuel()`);
- геттери для полів, які можуть знадобитись пізніше (`getInventoryNumber()`, `getFuel()` тощо).

Створіть у `Main` два-три об'єкти виведіть їхню інформацію через `getInfo()`.

## Крок 2. Абстракція (~10 хв)

**Пояснення.** Абстрактний клас — це клас, обєкт якого напряму створити не можна (`new Vehicle(...)` перестане працювати). Він задає спільний "контракт" для дочірніх класів через абстрактні методи — метод оголошується, але реалізацію відкладено на дочірні класи.

**Завдання.**

1. Зробіть рVehicle` абстрактним: `abstract class Vehicle { ... }`.
2. Додайте абстрактний метод:

   ```java
   public abstract String performMission();
   ```

   Він повинен описувати завдання, яке виконує техніка — але **кожен тип** техніки виконує його по-своєму (реалізуєте на крокі 4).

Після цього кроку проекта компілюватись не буде, доки не з"явиться хоча б один дочірній клас — це нормально, переходьте до кроку 3.

## Крок 3. Наслідування (~15 хв)

**Пояснення.** Наслідування дозволяє дочірньому класу отримати всі поля й методи батьківського класу через `extends` та додати власні.

**Завдання.** Створіть два дочірні класи:

```text
TransportVehicle extends Vehicle   → додаткове поле cargoCapacity (вантажопідйомність)
ArmoredVehicle   extends Vehicle   → додаткове поле armorLevel (рівень броні)
```

# кожного — свій конструктор, який викликає `super(...)` для спільних полів і встановлює власне поле.

Створіть у `Main` по одному об'єкту кожного типу і виведіть `getInfo()`.

## Крок 4. Перевизначення методів і поліморфізм (~15 хв)

**Пояснення.** `@Override` дозволяє дочірньому класу дати власну реалізацію методу з батьківського класу. Поліморфізм — це клас змінна оголошена типом `Vehicle`, а насправді містить об'єкт `TransportVehicle` або `ArmoredVehicle`, і виклик методу автоматично "потрапляє" саме в реалізацію потрібного класу.

**Завдання.**

1. У кожному дочірньому класі перевизначте `performMission()` зі своїм текстом, наприклад:

   ```text
   TransportVehicle → "Перевезення вантажу: ..."
   ArmoredVehicle   → "Транспортування особового складу: ..."
   ```

   Не забудьте `@Override`.

2. У `Main` створіть масив або список `Vehicle[]` / `List<Vehicle>`, покладіть туди обєкти обох типів і в циклі викличте `performMission()` для кожного. Переконайтесь, що виводиться саме "свій" текст для кожного об'єкта — це і є поліморфізм у дії.

## Крок 5. Метод `toString()` (~10 хв)

**Пояснення.** Коли ви пишете `System.out.println(vehicle)`, Java викликає метод `toString()` цього об'єкта. За замовчуванням він повертає щось на кшталт `Vehicle@1b6d3586`, що не інформативно — тому його зазвичай перевизначають.

**Завдання.** Перевизначте `toString()` у класі `Vehicle` так, щоб він повертав зручний опис техніки (номер, бренд, модель рік, паливо). Перевірте: `System.out.println(vehicle);` повинен вивести нормальний текст, а не адресу об'єкта.

## Крок 6. Методи `equals()` та `hashCode()` (~15 хв)

**Пояснення.** Оператор `==` для об'єктів порівнює не вміст, а посилання (чи це один і той самий об'єкт у пам'яті). Щоб порівнювати об'єкти "за змістом" (наприклад, за інвентарним номером), потрібно перевизначити лequals()`. А `hashCode()` — це "числовий відбиток" об'єкта, який використовують колекції на кшталт `HashSet`: два рівні за `equals()` об'єкти зобов'язані мати однаковий `hashCode()`, інакше `HashSet` та подібні колекції працюватимуть некоректно.

**Завдання.**

1. Створіть два об'єкти `Vehicle` з **однаковим** `inventoryNumber`. Порівняйте:

   ```java
   System.out.println(vehicle1 == vehicle2);        // false — різні об'єкти в пам'яті
   System.out.println(vehicle1.equals(vehicle2));   // поки теж false — equals() ще не перевизначено
   ```

2. Перевизначте `equals()` — два `Vehicle` вважаються рівними, якщо в них однаковий `inventoryNumber`. У більшості IDE це можна згенерувати автоматично (Generate → equals() and hashCode()), або написати вручну, перевіривши: чи це той самий об'єкт, чи `null`, чи сумісний тип, і лише потім — чи співпадає `inventoryNumber`.
3. Перевизначте `hashCode()` на основі того самого поля `inventoryNumber`.
4. Покладіть кілька об'єктів (включно з двома "однаковими") у `HashSet<Vehicle>` і виведіть розмір множини — переконайтесь, що дублікат не додався.

## Бонус — якщо лишився час

Необов'язково, але буде плюсом:

- **Перевантаження методів** — додайте до `Vehicle` ще один `refuel(double amount, String fuelType)` з іншим набором параметрів і покажіть роботу обох варіантів.
- **Третій тип техніки** — `SpecialVehicle` з полем `specialEquipment` і своєю реалізацією `performMission()`.
- **Клас `VehicleFleet`** — окремий клас, що зберігає список техніки всередині (`private List<Vehicle>`) і має методи `addVehicle()`, `findVehicle(String inventoryNumber)`, `showAllVehicles()`.
